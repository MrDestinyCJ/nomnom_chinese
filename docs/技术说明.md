# 技术说明：这个汉化补丁是怎么做出来的

作者：DSH 会话内完成 · 仅供学习交流

---

## 0. 一句话总结

游戏的资源档案里有完整的**多语言框架**，但 PC 版把**中文文本**和**中文字体**都阉割了。
补丁做的事就是：把文本表补齐 + 把字体补全 + 绕过语言白名单。

---

## 1. 资源档案格式（`data.pkdwin` / `data.pkiwin`）

游戏由 Double Eleven 移植，引擎（内部代号 GM）使用自研档案：

```
data.pkiwin  索引文件（41120 字节）
  偏移 0   : u32  版本 = 3
  偏移 4   : u32  保留 = 0
  偏移 8   : u32  条目数 = 2569
  偏移 12  : 条目数组，每条 16 字节：
             u32 原始大小(解压后)
             u32 压缩大小
             u32 在 pkd 中的偏移
             u32 名称哈希（只存哈希，不存文件名）
  文件末尾 : 4 字节尾部数据

data.pkdwin  数据文件（128 MB）
  偏移 0  : 12 字节头（与 pki 前 12 字节相同）
  偏移 12 : 各条目的 zlib 流，首尾相接，无空隙
```

要点：

- **索引里没有文件名**，只有 32 位哈希。所以补丁**按条目序号**替换，不需要（也无法轻易）猜文件名。
- 压缩为 **zlib**（`78 5E` 开头，即默认压缩级别）。
- 条目偏移完全连续，因此重建档案 = 重算偏移 + 重写索引，非常简单。
- 验证方法：把原档案「零改动重建」一次，若输出与原文件**逐字节一致**，说明格式理解正确。

## 2. 文本表 `gametext.utxt`（条目 #315）

```
编码：UTF-16LE，带 BOM(FF FE)，行分隔 CRLF
格式：TSV，16 列，2408 行
列序：TEXT_KEY / Font Filter / Max Char Length / Comment /
      Japanese / English / English UK / French / Italian / German / Spanish /
      Korean / Portuguese / Russian / Chinese_T / Chinese_S
```

游戏脚本里通过 `Q.NewLocDB("gametext.utxt")` 加载，语言由 `g_cur_lang` 决定。

**列映射的坑**：脚本中 `s_locdb_langs` 写的是
`JAPANESE=1, ENGLISH=2, ... CHINESE_S=12`，
而它在 TSV 里对应的是**第 15 列**，即 **引擎列号 = TSV 列号 − 3**。

### 语言是怎么被选中的

```javascript
// SetupLanguageSteam(): 读 Steam 语言
"s simplified chinese"  → s_locdb_langs.CHINESE_S
"traditional chinese"   → s_locdb_langs.CHINESE_T
// LoadGlobals(): 再用存档里的语言覆盖
if( ?data.language ) { global g_cur_lang = s_locdb_langs[ data.language ]; }
```

### 为什么菜单里没有中文

```javascript
global s_locdb_langs_used =
{
    false, true, true, false, true, true, true, true, false, false, false, false, false,
};
//      ↑日   ↑英   ↑英UK  ↑法   ↑意   ↑德   ↑西   ↑韩    ↑葡   ↑俄   ↑繁中 ↑简中
```

白名单里 `CHINESE_T / CHINESE_S` 都是 `false`，所以官方菜单永远不会出现中文。
补丁的做法是**借用「西班牙语」槽位**（索引 7，白名单为 true）承载中文，
并把这个菜单项的名字改成「简体中文」。这样不用改任何字节码。

## 3. 字体：为什么切中文会整屏没字

```javascript
// global_resources.gm
local font_prefix = "FontStd_";
local language = GetLanguageKey( g_cur_lang );
if( language == "CHINESE_T" || language == "CHINESE_S" )
{
    local font_prefix = "FontChina_";   // ← 这里的 local 让它只在块内生效
}
```

且 PC 包里**根本没有 `FontChina_*` 这套字体资源**，于是中文模式下字体创建失败，
所有文字（包括图片化的 UI）全部不渲染 —— 表现为「整屏一个字都没有」。

同时，日文（走 `FontStd_`）能正常显示汉字，说明这条渲染路径完全可用。

**补丁的做法**：把 `FontStd_` 槽位的字体换成游戏自带的 **Noto Sans CJK SC Bold**
（覆盖中日韩），于是中文槽位只要走「非中文语言」就能正常渲染。

## 4. 位图字体格式（`.fnt`）

AngelCode **BMF v3** 二进制格式，但有个变体：

```
"BMF" + 版本字节(0x03)
块结构：[类型 u8][大小 u32][数据]   （注意：不是标准 BMF 的 [类型 u16][大小 u32]）
  类型 1 = info    （字体名等）
  类型 2 = common  （行高、基线、页面尺寸、页数）
  类型 4 = chars   （字形记录，**没有计数字段**，数量 = 块大小 / 20）
  类型 5 = kerning （字距对）
```

字形记录 20 字节：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | u32 | Unicode 码位 |
| x, y | u16 | 在图集中的位置 |
| w, h | u16 | 位图尺寸（像素） |
| xoffset | i16 | 绘制左偏移 |
| yoffset | i16 | 绘制上偏移 |
| xadvance | i16 | 前进宽度 |
| page, chnl | u8 | 页号、通道 |

游戏里两套字体（`FontStd_` / `FontChina_`）实际对应两个条目：

| 条目 | 字体名 | 字形数 | 图集 |
|---|---|---|---|
| #833 | FOT-Kurokane Std EB | 1964 | #895 |
| #839 | Noto Sans CJK SC Bold | 2704 | #894 |

判断哪张图集配哪个字体：拿 `.fnt` 里的字形矩形去图集上采样，比较**矩形内墨迹率**与**边缘墨迹率**，
匹配度高的就是对应图集。

## 5. 字形图集格式（`.dds`）

```
标准 DDS 文件头(128 字节) + 2048×2048 的 8bit 数据
像素格式：pfFlags=0x2, fourCC=0(未压缩), bpp=8, R掩码=0, A掩码=0xff
即一张 A8（纯透明度）贴图
```

图集左下角区域基本是空的（原始占用率约 57%），补丁把新字形**货架式装箱**到空闲区。

## 6. 补齐字形的原理

### 6.1 校准渲染参数

拿图集里已有的字形当基准，反推渲染参数：

- **字号**：用系统字体 `NotoSansSC-VF.ttf` 在 24~37px 之间穷举，与图集字形尺寸比对 →
  **35px** 时平均误差最小（0.4~0.5px）
- **字重**：500~900 逐档比对墨量 → **wght 700** 时墨量比 0.954，最接近
- **观感**：原图集峰值透明度只有 ~170（不是 255），说明原字体做过柔化处理 →
  用 **高斯模糊 1.0 + 透明度 × 0.67** 复现，像素平均差从 51 降到 41

### 6.2 度量字段的拟合

`xo` 与渲染的左边界基本一致（平均偏差 −0.2px）。`yo` 没有直观的几何含义，
用 80 个已有字形做线性回归得到：

```
yo ≈ 143.559 + 2.476 * inkTop + 0.433 * inkBottom − 0.922 * h − 0.182 * w
残差 RMS = 0.96px（最大 2.35px）
```

CJK 字形的前进宽度统一为 **133**。

### 6.3 补充结果

- 本补丁用到的汉字共 **1908** 个，字体自带 828 个 → **补入 975 个字形**（含少量全角标点）
- 字形总数 **2704 → 3679**，图集占用率 57% → 80%，仍留 20% 余量

## 7. 打包与安装

补丁只替换 5 个条目：

| 条目 | 内容 |
|---|---|
| #0 | credits.utxt（职员表，清掉西语列避免串味） |
| #8 | eula.utxt（用户协议，同上） |
| #315 | gametext.utxt（**汉化文本表**，写入 Spanish 列 + Chinese_S 列） |
| #833 | `FontStd_` 字体（换成补全字形的 Noto CJK） |
| #895 | `FontStd_` 图集 |

`install.ps1` 的流程：

```
让用户指定游戏目录（弹出文件夹选择框，或把游戏文件夹拖到 .bat 上；不含默认路径）
  ↓ 首次安装时把原文件备份为 *.bak_zh
读原始 data.pkiwin / data.pkdwin（优先读 .bak_zh 备份，保证可反复安装）
  ↓ 把 patch_data 里**已压缩好的 zlib 字节流**直接搬进对应条目
    （所以安装器不需要任何压缩库，纯字节搬运）
  ↓ 重算所有条目偏移、重写索引
写出新的 data.pkdwin(128.8MB) / data.pkiwin
  ↓
把存档 globals.dat 中 7 字符的语言字段原地改成 "SPANISH"
```

整个安装器只用 Windows 自带的 PowerShell（`[System.IO.File]` + `[Array]::Copy`），
不需要 Python、不需要联网、不需要管理员权限。

语言字段长度相同（ENGLISH / SPANISH 都是 7 字符），所以可以**原地替换、不改文件大小**。

## 8. 验证方式

- 零改动重建与原档案**逐字节一致**
- 补丁后档案 **2569/2569 条**均可正常解压
- 补丁写入的条目与 `patch_data/` 中的数据**逐字节一致**
- 文本表：2154 条全部有译文，颜色标记 `<rrggbb>...<>` 与格式符 `%s/%d/%ls` 与原英文逐条对齐
- 游戏内实测：主菜单、选项、教程、建筑/研究菜单均正常显示中文

## 9. 已知限制

- 语言槽位借用的是 Español，游戏内部语言枚举没有改动
- 极少数超长句为适配排版做了精简
- 游戏更新后资源档案变化，需要重新制作（流程与工具见仓库脚本）
